# VacAssist——家用吸尘器多模态使用与故障诊断助手

**技术栈：** Python、FastAPI、LangGraph、LangChain、阿里百炼 Qwen、MinerU、BGE-M3、BGE-Reranker-v2-M3、Milvus、Neo4j、MongoDB、MinIO、PyMilvus、FlagEmbedding

## 项目描述

面向家用吸尘器说明书查询、日常维护和故障码排查场景，构建从 PDF 异步导入、多模态图文解析、产品型号确认、向量检索到证据约束回答的 RAG 系统。以 4 份松下官方中文说明书作为真实语料，完成 88 页文档、142 个文本切片和 185 张有效图片的全链路入库，并建立可复现的路由、检索和答案评测集。

## 个人工作与量化结果

- 基于 FastAPI `BackgroundTasks` 和 LangGraph 编排 MinerU 解析、图片处理、标题级切分、短片段合并、型号抽取、BGE-M3 向量化、Milvus/Neo4j/MinIO 入库流程；通过 `task_id` 提供异步任务状态和节点进度查询。
- 针对 MinerU 产生大量图标碎片的问题，按图片面积过滤无效对象，并增加 Markdown 图片摘要缓存；4 份手册从 508 张原始图片中保留 185 张有效图片，减少 63.6% 的视觉模型请求，同时支持失败任务断点复用。
- 建立独立产品型号向量集合，结合 Qwen 型号抽取与 Milvus Dense/Sparse 匹配完成标准型号归一化；通过含数字型号 token 的唯一映射和泛品类词拦截，16 题回归集型号路由准确率由 81.25% 提升至 100%，未知/泛称问题拒绝率由 66.67% 提升至 100%。
- 构建 32 题人工标注检索集并完成消融实验：Dense 检索取得 Hit@3 93.75%、Recall@5 100%、MRR 0.8995，平均检索耗时 0.53 s；HyDE+RRF 将 Hit@3 提升至 96.88%，但平均耗时增至 5.31 s，因此将 Dense 设为默认快速路径，完整增强链路保留为可配置模式。
- 对 Dense/Sparse 进行 6 组权重搜索，发现该型号过滤语料中增加 Sparse 权重会降低 Recall@5 与 MRR；据实选择 Dense 默认方案，而不是固定使用 0.5/0.5 混合权重。进一步验证 CPU Reranker 平均耗时 26.71 s 且 Hit@3 降至 90.62%，因此不进入默认在线链路。
- 实现基于证据编号的回答生成和引用格式归一化；在 8 题人工关键事实集上，关键事实召回率 93.75%、合法引用率 100%、答案通过率 87.5%，平均答案生成耗时 3.69 s。知识不足时返回拒答或型号澄清，避免跨型号引用。
- 对知识图谱 LLM 输出增加单切片异常隔离，使一条非标准 JSON 不再回滚整份文档；本次 4 份手册的文本、图片、产品型号和 142 个向量切片均成功保留，异常切片单独写入导入清单。

## 项目难点与技术决策

- **图文语义断裂：** 根据图片在 Markdown 中的位置抽取章节标题、上文和下文，结合视觉模型生成中文描述，上传 MinIO 后将语义标题与远程地址回写原文，使结构图和操作图能够参与召回及答案引用。
- **相似型号混检：** 在查询前先做型号标准化，并使用 `item_name` 作为 Milvus 标量过滤条件；型号不明确时返回候选项，不直接跨产品检索。
- **复杂链路不一定更优：** 通过 Dense、Dense+Sparse、HyDE+RRF、HyDE+RRF+Reranker 四组对照同时测量效果与延迟，最终保留“默认快速路径 + 可配置增强模式”，而不是为了堆叠组件牺牲在线体验。
